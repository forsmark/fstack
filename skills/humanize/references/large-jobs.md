# Large jobs

A large job is a check of a whole site, a set of mails, or every release note at once. One reader holding every unit in mind misses the patterns that return from page to page. Split the reading, then check the proposals before the person sees them.

1. **List the units.** Group them into areas a reader meets together: the sign-in flow, the account pages, the mails, the errors. Done when every unit is in exactly one area.
2. **Review each area read-only.** Start one review agent per area, in parallel. Give each one this skill's `SKILL.md`, `references/patterns.md`, the project's profile, and the paths of its units. Each agent runs steps 2 to 5 of the skill and proposes repairs, but changes no file. Ask each one to list the shapes it saw return, such as "every error ends on a joke", so patterns across areas show up.
3. **Review the proposals.** Start a second run that reads the first run's proposals against the old copy, area by area. It looks for three things: a fact, number, link or condition that a proposal dropped, a new template that the proposals share, and a cut that removes a required sentence. Done when each proposal is kept, mended or dropped, with a reason.
4. **Show before and after.** Present the result to the person as a page they can scan, with each unit's old and new strings side by side, the findings each change answers, and the patterns kept with their reasons. Legal text goes in a section of its own, one change per item, for the owner to decide.
5. **Apply what the person approves.** Then run step 7 of the skill on every changed unit.
